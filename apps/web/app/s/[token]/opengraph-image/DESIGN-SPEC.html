Galaxia OG Card Design Spec — MATCH TARGET

Purpose: This is the authoritative visual target for the OG share cards in PR #153. The PR version rendered flat (no glow, grey outline nodes, dead background) because the glow in the earlier chat mock used SVG blur filters that Satori ignores. This file is authored ONLY in techniques Satori (@vercel/og) actually renders, so it ports directly into the ImageResponse JSX. Match it.

SATORI CONSTRAINTS — obey these or the card breaks or flattens

1. Glow is done with radial-gradient backgrounds and box-shadow, NEVER filter: blur() or SVG feGaussianBlur (Satori ignores both — that is exactly why the PR cards are flat).
2. Every <div> with more than one child MUST set display:flex and an explicit flex-direction (Satori requirement).
3. No CSS variables (var(--x)) — Satori drops them. Use literal hex (this file already does).
4. Lines/rings = inline <svg> with plain <line>/<ellipse>/<path> strokes. No SVG filters.
5. Zodiac/planet glyphs need the subsetted symbol font in the fonts array (already planned in PR). In this preview your OS renders them; in Satori only the supplied font will.

THE GLOW RECIPE (the thing the PR missed)

A glowing node = a soft radial-gradient orb that fades to transparent, with a small bright core on top:
background: radial-gradient(circle, rgba(255,255,255,.9) 0%, <COLOR> 32%, transparent 70%) on a round div, plus a tiny white core div. That produces real bloom in Satori with zero filters. Flat stroked circles (what the PR shipped) are the wrong technique.

PALETTE (literal hex — use verbatim)

bg #09080f · violet bloom #5d4aa6/#382d64 · gold wordmark/eyebrow #ecc890/#d9b57e · gold core node #ffd98a · teal node #7fd4c0 · coral node #e8926a · lavender node #b8a9e8 · pale-yellow node #e8d98a · sign tile #5a3f8f · tile glyph #e6dcff · title text #f2eefa · muted #a99ec9/#b3a6cf · aspect coral #e8926a · aspect teal #7fd4c0

FONTS

Display/serif = Fraunces (names, signs, summary — italic for the summary line). Labels/UI = Inter. Glyphs = the subsetted symbol font. Wordmark is "Galax" + italic "ia".

SCOPE

Two cards only: chart (single) and comparison. The galaxy card is NOT here and NOT in this build — it is deferred behind a galaxy-share feature that does not exist yet (no galaxy snapshot kind, no per-share people selection). Do not attempt it.

Comparison card notes — the safety-critical ones:
1. The summary line is the app's RELATION_HEADLINE[relationType] for non-romantic types (siblings/friends/parent-child/ancestor) plus the new authored platonic line. Read the table directly, never compareHeadline() (its fallback reads scores).
2. For a romantic / partners pairing: render NO summary and NO relationship label. Replace with a neutral subtitle only (e.g. "A shared compatibility reading"). No scores, no warmth, no attraction copy, ever.
3. Sun/Moon/Rising per person; Rising tile only when that person's chart.asc exists. Never fabricate.
4. The relationship label (SIBLINGS) shows only for non-romantic types; hide it for romantic.
How to use this file: commit it to the repo (e.g. apps/web/app/s/[token]/opengraph-image/DESIGN-SPEC.html) and port each element into the ImageResponse JSX 1:1 — same hex, same positions, same glow technique (radial-gradient orbs + box-shadow). Open it in a browser to see the target. When your Satori render matches what the browser shows here, the card is right. The single biggest delta from PR #153: nodes and tiles must GLOW (radial-gradient + box-shadow), and the background must carry the violet bloom, not be flat #09080f.
