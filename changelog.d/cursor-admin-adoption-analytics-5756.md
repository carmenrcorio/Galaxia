## Feature adoption dashboard at /admin/analytics (branch `cursor/admin-adoption-analytics-5756`) — 2026-09-15

**Trigger**: The founder needs a read-only product-adoption snapshot (accounts, constellation, Vela/Compare, groups, engagement) behind the existing admin gate, not a new auth system and not a client-readable query.

`[DECISION]` **Authorization is `requireAdmin()` / `admin_users`, not an owner-email check.** `/admin/**` already has a layout gate (`apps/web/app/admin/layout.tsx`) that calls `requireAdmin()`, which verifies the cookie session then reads `admin_users` with the service role and decides via `@galaxia/core` `isAdmin()`. Middleware already sends anonymous `/admin` traffic to `/login?next=…`. `20260821191500_admin_role_foundation.sql` keyed the founder grant to a stable `auth.users.id` and recorded that nothing in this repo branches on a founder email. This page follows that. There is no `NEXT_PUBLIC_ADMIN_EMAIL`.

`[ADDED]` **`public.admin_adoption_metrics` view** (`20260915021648_admin_adoption_metrics.sql`). One row of cumulative counts plus last-7-day windows. Phase 0 on live `eigfvribtntbxyjutsma` found no existing usage-aggregation view or function (public has zero views). `threads` has `mode` (`ask`/`shared`), not `kind`; both modes are Vela conversations, so total Vela conversations is `count(threads)`. Compare sessions are `comparison_history` rows (`last_viewed_at` for the week window). `blog_email_captures` exists and is counted. New accounts use `auth.users.created_at`; active accounts use `last_sign_in_at`; deleted auth rows (`deleted_at is not null`) are excluded. Vela messages this week are `messages.sender = 'user'`. Memorial/ancient profiles are `passed_at is not null or relation = 'ancestor'`. Avg people per account excludes accounts with zero people (the average is over owners who have at least one `people` row).

`[ADDED]` **Service-role-only access on the view.** Views cannot carry RLS. Same revoke-from-`public`/`anon`/`authenticated` belt as `admin_users`, then `grant select` to `service_role` only. The view stays security_definer (Postgres default) so it can read `auth.users`; `security_invoker` would fail because `service_role` has no SELECT there.

`[ADDED]` **`/admin/analytics`** (`apps/web/app/admin/analytics/page.tsx`). Server component, `force-dynamic` / `revalidate = 0`, queries the view through a service-role client (`SUPABASE_SERVICE_ROLE_KEY`). Five number tables matching the metric groups, gold this-week deltas, a last-refreshed UTC timestamp, and a Refresh button (`router.refresh()`). Layout nav adds an Adoption link. Counts only: never a person name, note body, or Vela message.

`[CHANGED]` **The local `auth.users` replay stub** (`apps/web/lib/test-utils/auth-schema-stub.sql`) now includes `last_sign_in_at` and `deleted_at`, which GoTrue has and which `admin_adoption_metrics` reads. Without them, from-scratch replay of `20260915021648` dies (`column "deleted_at" does not exist`).
