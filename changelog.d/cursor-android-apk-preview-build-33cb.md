`[FIXED]` **`react-native-screens` pinned to `~3.31.1` (Expo SDK 51 target).**
The second build (`5a66c298-c5ff-4d70-9d2f-7eac72a45260`) got past prebuild but
died in the `Run gradlew` phase: the Metro release bundle failed in
`@react-native/codegen` with `Unknown prop type for "onAppear": "undefined"`
on `react-native-screens/src/fabric/ModalScreenNativeComponent.ts`. Cause:
`react-native-screens@4.25.2` (resolved as a floating peer of expo-router /
react-navigation) uses new-architecture fabric spec syntax that the RN 0.74
codegen bundled with SDK 51 cannot parse. Pinned to the SDK 51 bundled version
(`expo/bundledNativeModules.json` → `3.31.1`), which is the correct pairing for
react-navigation 6.x on RN 0.74. Verified locally: `expo export --platform
android` now bundles cleanly (1055 modules, exit 0). Screens is mobile-only, so
this does not touch the web app.

`[FIXED]` **Native modules pinned to their Expo SDK 51 versions.** The third
build (`14a112eb-38d6-4d03-9b15-bcb382cace04`) then failed in `Run gradlew` on
`:react-native-async-storage_async-storage:kspReleaseKotlin` —
`@react-native-async-storage/async-storage@3.1.1` requires Kotlin 2.1.0 / KSP,
but SDK 51 (RN 0.74) builds with Kotlin 1.9.23. Pinned
`@react-native-async-storage/async-storage` to `1.23.1` and, for the same
too-new-for-SDK-51 reason, `react-native-safe-area-context` to `4.10.5` (both
from `expo/bundledNativeModules.json`; both mobile-only). Left `react`,
`react-native`, `typescript`, and `@types/react` at their current versions:
those are JS/dev-only (no bearing on the Kotlin gradle compile) and `react` /
`typescript` are hoisted and shared with `@galaxia/web`, which is green on the
current versions.
