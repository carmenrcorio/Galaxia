## Blog posts move from static config to Supabase-backed admin CMS (branch `cursor/blog-posts-admin-cms-5e37`) — 2026-09-09

**Trigger**: `/blog` (PR #159) read from a hand-maintained `BLOG_POSTS` array — only a developer could publish. Carmen needs to add posts and photos herself.

`[ADDED]` New `public.posts` table (supabase/migrations/20260909011620_blog_posts_schema_and_content.sql) — the first table in this schema that is genuinely public-readable (RLS grants SELECT to anon/authenticated, but only where `status = 'published'`; every write is service-role only, mirroring `profiles.comped`'s admin-only write posture). A public `post-images` Storage bucket backs hero + inline images; reads use the public-bucket URL mechanism (no RLS policy needed), writes are service-role only via `/api/admin/posts/images`.

`[ADDED]` Admin posts UI at `/admin/posts` (list, create, edit, delete), mirroring `/admin/users`'s layout/auth/service-role pattern exactly — same `requireAdmin()`/`requireAdminApi()` guard, same `glass-card`/`pill-link` styling, same `writeAdminAuditLog` contract (new `create_post`/`update_post`/`delete_post` audit actions). The body editor is a markdown textarea with an "Insert image" button (uploads through the same image endpoint the hero-image field uses) — no new rich-text/WYSIWYG dependency, matching the `react-markdown`/`remark-gfm` already in `apps/web/package.json`.

`[CHANGED]` `/blog`, `/blog/[category]`, and the post template (`lib/blog.ts`) now read published posts from Supabase instead of the static `BLOG_POSTS` array. The per-article hand-authored JSX route (`app/synastry-chart-meaning/page.tsx`) is replaced by one generic `app/[slug]/page.tsx` template that renders any post's markdown body — same URL (`/synastry-chart-meaning`), no redirect needed, since Next.js resolves static routes ahead of a same-level dynamic segment. `sitemap.ts` now lists post URLs dynamically from published rows instead of a hardcoded path.

`[DECISION]` The existing synastry post's content was migrated verbatim into the new table (same seed migration) so it becomes editable through the new admin going forward. Its `hero_image_url` is left `null` — assigning one is a real content task for Carmen through the new admin, not something to fabricate here (Part C of this work renders gracefully with no hero image).

Verified live: applied the migration to the one real Supabase project (`eigfvribtntbxyjutsma`), then round-tripped the full admin flow in a browser against it — created a draft post, confirmed it was absent from the public `/blog` list, published it, confirmed it appeared with the updated dek, confirmed its markdown body rendered correctly at its own URL, then deleted it. Test admin account and any uploaded test image were removed afterward; the live `posts` table now holds only the migrated synastry post.
