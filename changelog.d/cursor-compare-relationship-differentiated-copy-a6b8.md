## Relationship-differentiated Compare copy (branch `cursor/compare-relationship-differentiated-copy-a6b8`) — 2026-08-19

**Trigger**: RELATION_ASPECT_FRAME / `whatTheyNeed()` audit found relationship type was mostly a cosmetic prefix over otherwise sign-driven copy — a sibling and a friend with the same Mercury sign read identical "in practice" guidance, the Compare headline was score-only with no relationship framing, and a relationship-framed aspect reading (`relationshipAspectFraming()` / `RELATION_ASPECT_FRAME`) had been silently dropped in `134413a`. Three founder-authored, founder-approved copy changes, wired into the existing shared `@galaxia/astro` engine — no new astrology, no new claims, no minor-safety changes.

`[CHANGED]` **Siblings and friends now read genuinely different Mercury "how" guidance for the same sign** (`packages/astro/src/compare-guidance.ts`). Replaced the shared `MERCURY_HOW` map + `"Between siblings"` / `"As friends"` prefix with two dedicated tables, `SIBLING_MERCURY_HOW` and `FRIEND_MERCURY_HOW`, each keyed by the person's real, engine-computed Mercury sign. `whatTheyNeed()` now selects the sibling or friend table by `relType` instead of reading one shared map twice. No other relationship type's path changed. Founder-authored verbatim; tagged `FOUNDER-REVIEW: authored`.

`[ADDED]` **Relationship-framed Compare headline** (`compareHeadline()` in `packages/astro/src/compare-guidance.ts`). The result headline is now keyed by relationship type — one flat line each for `partners`, `siblings`, `friends`, `parent-child`, and `ancestor` — replacing the previous score-band-only line at the top of a reading. Any relationship type not offered by the saved-people picker (`romantic`, `platonic`) falls back to the original score-band line rather than inventing copy. `compareHeadline()` is the single source both web (`/app/compare`) and mobile (`Compare`) call, closing a pre-existing wording drift between the two surfaces (mobile previously had its own, differently-worded score-band headline). Founder-authored verbatim; tagged `FOUNDER-REVIEW: authored`.

`[ADDED]` **Revived `relationshipAspectFraming()` inside the shared `FlowsAndCatchesSection`** (`apps/web/components/flows-and-catches-section.tsx`, feeding `/app/compare`, `/chart/compare`, and `/s` snapshots). Only the `text` field is rendered — a relationship-framed sentence naming both people and the real aspect via the untouched, reused `RELATION_ASPECT_FRAME` strings. The `action` field is deliberately discarded: it is the exact same opener+tactic pair the section already renders via `aspectActionParts()`, so surfacing it again would be word-for-word repetition — the specific problem this revival exists to avoid, not reintroduce. `nameA`/`nameB` props were added to `FlowsAndCatchesSection` and wired at all three call sites.
