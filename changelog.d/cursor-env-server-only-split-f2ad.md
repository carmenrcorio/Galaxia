## Split `lib/env.ts` into client-safe + server-only modules (branch `cursor/env-server-only-split-f2ad`) — 2026-08-20

**Trigger**: security audit found private env var NAMES (not values, which never appeared in the bundle) leaking into the client bundle because `apps/web/lib/env.ts` exported `publicEnv`, `privateEnv`, and `revenueCatEnv` from one module — any client component importing `publicEnv` dragged the whole module, including the unused private object literals, into the client chunk.

`[FIXED]` **`privateEnv` and `revenueCatEnv`'s secret fields now live in `apps/web/lib/env.server.ts`, guarded by `import "server-only"`.** `lib/env.ts` keeps only `publicEnv`, `missingEnvMessage`, and `getSiteUrlFromRequestOrigin`, so client components pull in nothing but `NEXT_PUBLIC_*` values. The `server-only` package (official Next.js marker) now hard-fails the build if any client code ever imports the server module, turning this class of leak into a compile error instead of a bundle-size audit finding. `revenueCatEnv.publicKey` was dropped as a duplicate of `publicEnv.revenueCatPublicKey` (no call site used the mirror). Pure module reorg: no env values changed, no secrets rotated, no runtime behavior changed — the 8 server-side importers (`lib/invites.ts`, `lib/quick-share-server.ts`, and 6 route handlers) just import `privateEnv`/`revenueCatEnv` from the new path.
