## Settings subscription panel hang (branch `cursor/fix-settings-subscription-hang-05f1`) — 2026-09-14

**Trigger**: The Settings subscription card never left "Loading subscription…". It treated a missing `profiles.subscription_status` as an infinite load, ignored profile errors, and awaited a client RevenueCat `getCustomerInfo()` call with no timeout.

`[FIXED]` **Settings subscription panel reads `profiles.subscription_status` only.** The hang was not the dashboard entitlement id (`GalaxiaMea App Unlimited` is already correct in `RC_ENTITLEMENT_ID`). The panel was waiting on `@revenuecat/purchases-js` `Purchases.getCustomerInfo()` for a management URL, and on a profile fetch that could fail or never return; a null status rendered as loading forever. The card now loads billing columns from `profiles` with a 2s timeout. Timeout or error shows what is known plus `help@galaxiamea.com` (the same address as the CAN-SPAM footer in `apps/web/lib/emails.ts`). Null status after a successful read is an honest unknown, not a spinner.

`[CHANGED]` **Access copy uses `@galaxia/core` `hasAccess` and `trialDaysRemaining`.** Trial users see days remaining and the trial end date; paid users see plan name (from `profiles.plan`) and renewal date; cancel and a manage-billing mailto stay available. The client never writes entitlement columns. The RevenueCat webhook remains the only writer of paid status.
