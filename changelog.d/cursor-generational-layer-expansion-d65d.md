## Generational Layer expansion: Corruption Signature, historical figures, era events, Family Bridge (branch `cursor/generational-layer-expansion-d65d`) — 2026-09-12

**Trigger**: the person chart page's "Generational layer" accordion (Uranus/Neptune/Pluto) only showed a one-line tagline + description per sign. We wanted the Pluto row to carry more weight — how the generation's power went wrong historically, who shared the signature, and what era they lived through — plus a generation-name header and, when viewing someone else's chart, a short Family Bridge paragraph connecting the viewer's and subject's Pluto signs.

`[ADDED]` New static content library `packages/astro/src/generational-layer.ts`, exported from the package index: `GENERATION_BY_YEAR` / `generationNameForYear` (birth-year → generation name + span, no gaps between ranges), `PLUTO_SIGN_EXTENDED` (per confident Pluto sign: `corruptionSignature`, 0-5 `historicalFigures`, `eraEvents` — Capricorn intentionally ships with an empty `historicalFigures` array rather than a fabricated one, per §12), and `FAMILY_BRIDGE` / `getFamilyBridge` (authored viewer-Pluto → subject-Pluto pairs only; unauthored pairs return `null` and render nothing). Covered by `packages/astro/test/generational-layer.test.ts` (12 tests).

`[ADDED]` `apps/web/app/app/person/[id]/page.tsx`: the Generational layer section now shows a generation name + birth-span line (derived from the already-loaded `person.birth_date`, no new fetch). The Pluto `ExpandRow` renders three new blocks in its expanded state ("The corruption signature," "Others who carried this," "What they lived through" as tap-to-reveal chips) — gated strictly on `chart.generational.pluto.confident === true`, so a year-only birth whose Pluto sign is ambiguous never renders a guessed sign's content. Uranus and Neptune rows are unchanged.

`[ADDED]` Family Bridge card: rendered only when `!person.is_self`, both the viewer's and subject's Pluto signs are confident, and an authored pair exists. The viewer's own confident Pluto sign is fetched once per profile load (mirrors the existing `owner_id` + `is_self` self-person lookup already used elsewhere on this page) and never fabricated from an unconfident sign.

`[DECISION]` The authored content was pasted verbatim per explicit instruction (no paraphrasing, no additions/removals). It contains em dashes (U+2014), which trips the repo's permanent `no-em-dash-user-copy` gate (`ENGINEERING.md` §15). Left as-is pending a founder decision on how to reconcile the two — see PR description.
