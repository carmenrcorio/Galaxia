## Retire the standalone "Family" tab; merge chart grid into Groups (branch `cursor/groups-relationship-dashboard-c8b8`) — 2026-09-10

**Trigger**: Report that the app nav had both a "Family" tab and a "Groups" tab. The "Family" tab (`/app/family-compare`, Generations Feature 2's personal-planet chart comparison) picked any 3-8 people from the constellation — nothing about it was actually family-specific — but its own copy and framing baked in "family" everywhere, so it read as a second, narrower group feature living next to Groups instead of a capability of Groups.

`[CHANGED]` **One tab for any group kind.** Removed the `/app/family-compare` nav link (`components/app-nav.tsx`). The old route now redirects to `/app/groups` (`app/app/family-compare/page.tsx`) so existing links/bookmarks don't 404. The dashboard's "Compare family" button (`app/app/page.tsx`) now reads "Compare as a group" and points at `/app/groups`.

`[ADDED]` **`ChartGridSection`** (`components/groups/chart-grid-section.tsx`) — the Sun/Moon/Rising/Mercury/Venus/Mars comparison table + shared-placement/element-clustering pattern read, now rendered on `/app/groups` (after Pair Dynamics, before the Manage Group accordion) for the currently loaded group's members, whatever the group's kind. It runs off a dedicated effect keyed on `selectedPersonIds` — independent of the generational cohort above it, so it renders even when a member lacks a computed generational signature or when the cohort reading was hydrated from a stored note (which has no chart data attached). Table/pattern logic (`detectFamilyPatterns`) is unchanged — this is a presentation move, not a new astrology computation.

`[FIXED]` **De-familyized the interpretation copy** (`packages/astro/src/family-compare-interpretations.ts`): "what this family shines toward...", "This family runs hot as a group", etc. → "this group" throughout, so the same static copy is honest for a friend group, a coworker group, or a family. Exported function names/signatures and existing test assertions (`family-compare.test.ts`) are unchanged — the tests never asserted on the literal word "family".

Unchanged: the `groups`/`group_members` data model, `detectFamilyPatterns`/`extractFamilyPlacements` computation, and the `family` option in the group-kind tag selector (siblings/friends/family/group) — a family is still a valid *kind* of group, it's just no longer a separate feature.

Verified: `pnpm typecheck` and `pnpm test` pass. Manually smoke-tested against the same live Supabase test account used for the Groups rework: confirmed the nav has no "Family" link, the dashboard button reads "Compare as a group" and lands on `/app/groups`, `/app/family-compare` redirects there automatically, and the new Chart grid + Patterns sections render correctly on an existing saved group with group-generic copy ("...runs the group", not "...runs the family").
