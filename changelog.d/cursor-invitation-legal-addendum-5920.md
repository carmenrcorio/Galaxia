## Invitation-flow legal addendum in Privacy Policy and Terms (branch `cursor/invitation-legal-addendum-5920`) — 2026-09-13

**Trigger**: The invitation feature (the existing `birth_data` flow, and the planned `constellation_connect` flow whose schema merged in PR #217) lets a user send a link that has someone else submit their own information directly to Galaxia. Neither legal document said anything about who sends that link, what the invited person is agreeing to, or how their submitted information is handled, so the feature had no coverage in either document.

`[ADDED]` **Terms of Service Section 6 ("Adding other people"), four new paragraphs** appended before the section's closing rule: **Invitation feature** (Galaxia does not send the invitation on the user's behalf), **Your representations** (the user represents a personal/preexisting relationship and no unsolicited or bulk use), **Consent by the invited person** (accepting and submitting information, or signing up, is deemed consent to the Privacy Policy), and **Platform role and indemnity** (Galaxia only transmits/stores what the two parties share; the user indemnifies Galaxia Mea LLC for misuse of the feature). Same bold-lead-in-paragraph style as the rest of the section, no sub-numbering.

`[ADDED]` **Privacy Policy Section 5 ("People you add"), four new paragraphs** appended before the section's closing rule: **Information from invitations** (the invited person submits their own information directly; Galaxia does not collect their name/email/phone to send the invitation, since Galaxia never sends it), **How we use it** (only to complete the profile/connection and, where chosen, show the shared chart; no independent marketing or contact), **Retention** (an unaccepted invitation link expires after 14 days and carries no information forward; accepted invitations fold into the normal profile retention/deletion terms), and **Rights of the invited person** (access/correction/deletion via help@galaxiamea.com, same as any other person in a user's galaxy).

`[DECISION]` **No renumbering.** Both additions are appended paragraphs within their existing section, before that section's closing horizontal rule; no heading numbers changed. Grepped the repo first for any email template, in-app copy, or other file that references a Privacy/Terms section number, confirmed none exists that this addition affects.

`[DECISION]` **Every new paragraph is tagged `FOUNDER-REVIEW`** (one HTML comment per paragraph, pointing back at this fragment), matching the PR #204-era convention already used elsewhere in both documents for agent-authored legal copy pending founder/counsel review. No em dashes (U+2014) in any inserted text, verified after insertion (the two markdown files are outside the automated em-dash gate's scan roots, so this was checked manually).

`[FIXED]` **`readLegalMarkdown` (`apps/web/lib/legal-content.ts`) now strips HTML comments before handing markdown to `LegalDocument`.** Found while verifying this change renders correctly: `LegalDocument`'s `react-markdown` has no `rehype-raw` plugin, so an `<!-- ... -->` comment was never actually dropped, it rendered as literal escaped text on the live page. That was already true of the two pre-existing `FOUNDER-REVIEW` comments in Terms Section 5 ("Plans" / "Automatic renewal") before this branch touched anything; it would have shipped 8 more visible comment blocks across `/privacy` and `/terms` if left alone. The source `.md` files still carry every marker (old and new) verbatim for grep/review; only the render path changed. New test: `apps/web/lib/legal-content.test.ts`.

Verified: `/privacy` and `/terms` render the new paragraphs correctly with no leaked comment text (manual browser check, before/after screenshots); `pnpm typecheck` passes with zero errors across all 6 packages; `pnpm --filter @galaxia/web test` passes (797 tests, up from 794: +3 new in `legal-content.test.ts`); the existing JSON-LD presence test (`apps/web/lib/seo-crawl-foundations.test.ts`) still passes, as expected, since it only checks for the `WebPageJsonLd` import string and never touches prose content.
