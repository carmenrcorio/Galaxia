## Open Graph tags for `/` and every marketing route (branch `cursor/marketing-og-tags-62ec`) — 2026-08-31

**Trigger**: LAUNCH BLOCKER — the Reddit launch post links to `galaxiamea.com` (the landing page `/`), and `/` had no Open Graph metadata at all, so the link unfurled as a bare gray URL with no image. `#153` (`cursor-og-share-images-phase0-780b.md`) added OG only to `/s/<token>` share pages; `/` and the rest of the marketing surface (`/login`, `/signup`, `/terms`, `/privacy`, `/chart`, `/download`, `/start`, `/welcome`, etc.) never got any.

`[ADDED]` **`apps/web/public/og-image.png`** — a static 1200x630 branded card (deep violet `#0a0717` background with a soft radial bloom, gold "Galax*ia*" Fraunces wordmark, the "your inner circle" eyebrow, and the hero's own tagline "Understand the people you love, through their real charts."). Rendered once with `next/og`'s `ImageResponse` (reusing the same Fraunces/Inter `.ttf` files `#153` committed under `app/s/[token]/opengraph-image/fonts/`) and committed as a plain static asset — this is the site-wide default image, not a per-request route, since the landing/marketing pages have no per-visitor data to render.

`[ADDED]` **`app/layout.tsx`** now sets `openGraph` (`title`, `description`, `siteName`, `type: "website"`, `images: [og-image.png]`) and `twitter` (`card: "summary_large_image"`, matching title/description/image) alongside the existing `title`/`description`/`metadataBase`. Every route that does not define its own `openGraph`/`twitter` inherits this whole object as-is (Next merges metadata per top-level key, not deep-per-field, so a partial override would silently drop the rest) — this is what fixes the bare-link unfurl for the marketing routes that had no metadata of their own (`/login`, `/signup`, `/download`, `/start`, `/welcome`, `/chart`, `/chart/compare`, `/r/[slug]`) and for the ones that only set `title` (`/terms`, `/privacy`). `metadataBase` was already added by `#153` from `publicEnv.siteUrl` (falling back to the existing prod URL) — confirmed unchanged and reused so the image URL resolves absolutely for crawlers.

`[ADDED]` **`app/page.tsx`** now exports page-specific `metadata`: a real title ("Galaxia — Astrology for the People You Love", replacing the generic "Galaxia" every route falls back to) and description drawn from the hero copy, plus its own full `openGraph`/`twitter` objects (restating the same `og-image.png`, since defining `openGraph` on the page fully replaces — does not merge with — the layout's version). This is the page the launch link actually points at, so it gets the most specific copy rather than relying on the site-wide default.

`[OPEN]` `/s/[token]`'s per-token `openGraph`/`twitter` (added in `#153`) already fully overrides the layout defaults with the token-specific image, so this change does not affect share-link unfurls — only routes with no `openGraph` of their own (which is now every marketing route) pick up the new fallback.

Verified: `next build` + `next start` with `NEXT_PUBLIC_SITE_URL=https://galaxiamea.com` (the real launch domain) set at build time, then fetched raw HTML — `og:title`, `og:description`, `og:image` (absolute `https://galaxiamea.com/og-image.png`, 1200x630), `og:type`, `twitter:card=summary_large_image`, and matching `twitter:*` tags are all present on `/`, and the site-wide defaults (generic title/description/image) correctly appear on `/terms` and `/login` as a control.
