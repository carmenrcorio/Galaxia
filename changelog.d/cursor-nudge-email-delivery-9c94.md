## Nudge delivery Phase B2: email + consent + unsubscribe (branch `cursor/nudge-email-delivery-9c94`) — 2026-08-21

**Trigger**: B1 (`feat/server-nudge-job`) computes and writes `person_daily_nudges` rows server-side but never emails anyone. This phase adds the actual delivery — the "your sky today" email, opt-out consent, a one-click no-login unsubscribe, the minor-exclusion-at-send gate, and the scheduling design — turning the feature on end to end. Diagnosed read-only first (Phase 0), approved, then implemented.

**Phase 0 — confirmed before writing code**: no existing HMAC/signing pattern in this repo; the two closest precedents are static-secret bearer comparison (`CRON_SECRET`/`REVENUECAT_WEBHOOK_AUTH`, `verifyWebhookAuth`) and the `quick_share_snapshots.share_token` random-UUID-plus-service-role-lookup pattern. `orderSkyRowsForHome` (`packages/astro`) already exists and is exactly what `/app` home uses to decide whose sky leads the constellation — reused unmodified for picking which nudge leads the email, rather than inventing new selection logic.

`[DECISION]` **Consent is opt-out, default-on** (`profiles.daily_nudge_emails_enabled boolean not null default true`), owner-writable from Settings via the same column-grant pattern as `timezone`/`house_system` — no new API route, no new row policy (profiles RLS already scopes every write to `id = auth.uid()`). This retroactively opts in every existing account the moment the migration lands; that is the locked founder decision, not a bug, but it raises the bar on the first send (see below).

`[ADDED]` **No-login unsubscribe token** (`profiles.unsubscribe_token uuid unique default gen_random_uuid()`), never granted to `anon`/`authenticated` — reuses the `quick_share_snapshots` pattern instead of introducing a new HMAC secret. Identifies exactly one user by construction (unique column), so a token minted for user A cannot structurally affect user B.

`[ADDED]` **`apps/web/app/api/nudge-email/unsubscribe/route.ts`** — no session, no `CRON_SECRET`, service-role client. `GET` (visible footer link) shows an HTML confirmation page; `POST` (RFC 8058 one-click, driven by the `List-Unsubscribe`/`List-Unsubscribe-Post` headers) returns a blank 200 with no redirect, per both the RFC and Resend's own guidance. Idempotent (flipping an already-false value, or a token matching no row, is a safe no-op) and cross-user-safe (unique-column lookup).

`[ADDED]` **`skyTodayEmail`/`nudgeEmailSubject`/`nudgeEmailHeaders`** in `apps/web/lib/emails.ts`, mirroring the existing `shell`/`p`/`button` trial-email primitives. Renders `copy_resolved` verbatim — no new safety/precision logic, since `minor_safe`/`precision_mode` are already baked in by the copy resolver at generation time. Subject line (`nudgeEmailSubject`) takes ONLY a person's name as its parameter — structurally cannot receive `copy_resolved` or a theme/domain word, so it can never leak the sentence to an inbox/lock-screen preview. `sendEmail` gained an optional `headers` parameter (backward compatible, trial emails unaffected) to carry the RFC 8058 pair. Footer includes a `[MAILING ADDRESS]` placeholder mirroring the same open placeholder in `content/legal/privacy-policy.md` — **FOUNDER-REVIEW: real address required before this ships to any real recipient** (CAN-SPAM).

`[ADDED]` **`apps/web/lib/nudge-send.ts`** — pure, unit-tested gate logic with no `server-only` import: `isDueForNudgeSend`/`ownerLocalHour` (hourly-cron local-hour check, solving the "single daily UTC cron can't hit 9am everywhere" problem without fabricating a fallback hour), `eligibleForEmailSend` (minor-exclusion + defensive passed-filter), `pickLeadNudgeRow` (one nudge leads per owner per day — never a digest — via `orderSkyRowsForHome` unmodified).

`[ADDED]` **`apps/web/app/api/cron/nudge-send/route.ts`** — a route SEPARATE from B1's compute job (reads already-written `person_daily_nudges` rows; never writes them, never touches `planDailyNudgeWrites`/`buildPersonDailyNudge`). Per-owner gates, in order: consent (query filter) → local-hour-due → minor-exclusion (+ defensive passed-filter) → lead selection → already-sent-today ledger, checked LAST right before sending. The consent → minor-exclusion → lead-selection relative order is the LOCKED critical property: minor-exclusion runs BEFORE lead selection, so the subject line's person name can never be a minor's, regardless of how "notable" a minor's transit is that day. An owner with only minor-subject content that day is skipped entirely — never falls back to a filtered-out row.

`[ADDED]` **Defensive minor recomputation, `effectiveMinorSafe`** (`lib/nudge-send.ts`): ORs the row's frozen `minor_safe` with a fresh `isMinorForSafety` recomputation over the SAME `people` row the send job already joins for the passed-person check — near-zero extra cost (the birth fields ride along on that existing join), strictly more protective (over-protect doctrine: only ever adds exclusions, never removes one), and goes through `isMinorForSafety` rather than reading `is_minor` raw.

`[ADDED]` **`daily_nudge_emails` idempotency ledger**, primary-keyed on `(owner_id, date)` — not per-person — enforcing "one email per owner per day" at the database level, mirroring the `trial_emails` ledger shape exactly (service-role only, no client policies). Cleared on account purge alongside `person_daily_nudges`.

`[ADDED]` Settings → "Daily sky email" toggle (`apps/web/app/app/settings/page.tsx`), same direct-`.update()`-on-own-row pattern as the existing House system card.

`[DECISION]` **One nudge leads, never a digest** — founder-approved in Phase 0. A user with five people gets one "your sky today" naming whichever person's row the reused `orderSkyRowsForHome` picks, not a five-item list.

`[DECISION]` **Scheduling: hourly cron, per-owner local-hour check, not a single daily UTC cron** — founder-approved in Phase 0. Point a Vercel dashboard cron (or Supabase `pg_cron`) at `nudge-send` every hour; `isDueForNudgeSend` filters to the subset of owners whose local clock just reached 9am. No committed `vercel.json` (`ENGINEERING.md` §2 — deliberately none in this repo).

`[OPEN]` **Physical mailing address placeholder** (`[MAILING ADDRESS]`, matching `content/legal/privacy-policy.md`'s own open `[MAILING ADDRESS]` bracket) must be filled with a real address before any real recipient receives this email — CAN-SPAM requires one in every commercial email. No fake address was ever hardcoded. Until it's filled, the send job may be built and exercised against a single test recipient, but the out-of-band cron trigger itself must stay unconfigured for the real `profiles` table — this repo already has no committed `vercel.json`, so no automatic send happens until a human explicitly wires one, which is the natural gate. Also open: the `RESEND_FROM` sending domain (`galaxia.app`) vs. the legal-entity domain used elsewhere (`galaxiamea.com`) — worth a founder confirmation that these are intentionally different.

`[FIXED]` **Copy style pass: no em dashes in newly-authored chrome copy.** The Settings toggle labels/status text and the email's first-send context line originally used em dashes; replaced with parentheses/periods per founder direction (`On (turn off)` / `"Saved. Daily sky emails are on."` / the first-send line now reads "...member - turn it off any time from the link below."). `copy_resolved` itself is untouched and legitimately keeps its em dashes (the astrology copy library's existing voice, `packages/astro/src/transit-nudge/copy-matrix.ts`) — the rule applies only to copy this phase authored, not to the frozen sentence it renders.
