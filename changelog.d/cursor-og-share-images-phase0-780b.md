## OG image routes for chart + comparison shares, `/s/` unfurl meta tags (branch `cursor/og-share-images-phase0-780b`) — 2026-08-27

**Trigger**: A copied `/s/<token>` link unfurled as a bare URL with no preview. Phase 0 diagnosis (prior turn) confirmed `next/og`'s `ImageResponse` ships inside the installed `next@15.5.23`, that Satori needs raw font bytes (no `next/font/google`), that the zodiac/planet glyphs are outside Fraunces/Inter's coverage, and that `RELATION_HEADLINE`/`FORBIDDEN_PII_KEYS` needed to become exported for safe direct reuse. Galaxy (the `/app` constellation) is out of scope — no galaxy share kind exists.

`[ADDED]` **`apps/web/app/s/[token]/opengraph-image.tsx`** — one branching OG image route (`snapshot.kind === "single"` → chart card with a decorative 12-sign wheel + Sun/Moon/Rising chips; `"compare"` → two-person Sun/Moon/Rising panels + a relationship-appropriate summary; unknown/forged/missing token → a generic branded fallback card, never a broken unfurl). 1200x630 PNG. Renders only the already-stripped stored snapshot (same `getQuickShareByToken` the page uses) — never recomputes a chart, never reads `synastry.scores`, never calls `whatTheyNeed`/`compareHeadline`. Reads `RELATION_HEADLINE` (now exported from `@galaxia/astro`) directly instead, because `compareHeadline`'s fallback for an uncovered type needs a score-derived `overall`.

`[ADDED]` **`apps/web/lib/og-card.ts`** — the pure, unit-tested data-shaping layer the route imports: `extractOgBigThree` filters placements by `confident !== false` (matching `getSign`'s guard in `share-snapshot-view.tsx`) and only ever reads `chart.asc` for rising, never fabricating one; `resolveOgCompareSummary` returns the authored `OG_NEUTRAL_COMPARE_SUBTITLE` for any `isRomanticRelation` type (imported from `@galaxia/astro`, never a string check) and otherwise `RELATION_HEADLINE[type]`, falling back to the new authored `OG_PLATONIC_SUMMARY` (the one non-romantic type that table omits) and only then to `generational.theme`. `buildOgCompareCard` runs the existing `effectiveCompareFraming` backstop first, so a bad romantic+minor row still renders platonic here too.

`[ADDED]` Five static font files under `app/s/[token]/opengraph-image/fonts/` (Fraunces regular/semibold, Inter regular/semibold — static instances pinned from the same variable families `app/layout.tsx` loads via `next/font/google`, since Satori needs raw `.ttf` bytes — plus a merged `ZodiacGlyphs-Regular.ttf` subset to exactly the 22 codepoints `SIGN_GLYPH`/`BODY_GLYPH` use). All read once via a top-level `await Promise.all([readFile(...)])`, never inside the request handler. Total ~272KB, inside the 500KB `ImageResponse` bundle cap. Provenance and regeneration steps are in `fonts/NOTICE.md`.

`[ADDED]` `generateMetadata` in `app/s/[token]/page.tsx` (replacing the static `metadata` export) sets `openGraph.images`/`twitter` (`summary_large_image`) to the sibling `opengraph-image` route for the token, keeping `robots: { index: false, follow: false }` unchanged. `metadataBase` added to `app/layout.tsx` from `publicEnv.siteUrl`, falling back to the existing prod URL already used by the cron routes — without it a relative `og:image` never resolves for a crawler that has no request origin.

`[CHANGED]` `RELATION_HEADLINE` (`packages/astro/src/compare-guidance.ts`) and `FORBIDDEN_PII_KEYS` (`apps/web/lib/quick-share.ts`) are now exported — both already existed, this is a visibility change only, so safety-critical callers (the OG route and its tests) can reuse the single source of truth instead of a second copy.

`[ADDED]` Structural safety tests: `apps/web/lib/og-card.test.ts` iterates the full `RelationType` union (via the same `[...COMPARE_RELATION_TYPES, "romantic", "platonic"]` construction `quick-share.ts` uses internally) asserting no `FORBIDDEN_PII_KEYS` key and no populated score value/key ever appears in a built card, and that romantic types always get the neutral subtitle while non-romantic types always get a real relationship line; plus rising-omitted-without-`chart.asc` and confident-filter coverage. `apps/web/lib/og-share-route-wiring.test.ts` reads the route/page/layout source directly (same pattern as `comp-route-wiring.test.ts` — importing the route pulls in `server-only` via `quick-share-server.ts`, which throws outside a Next server bundle) to prove the route never touches `.scores`/`.synastry`/`whatTheyNeed(`/`compareHeadline(`, reads fonts at module scope, and that the page/layout wire up `generateMetadata`/`metadataBase` correctly.
