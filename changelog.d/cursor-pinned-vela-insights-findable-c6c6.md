## Pinned Vela insights: search, theme, sort (branch `cursor/pinned-vela-insights-findable-c6c6`) — 2026-09-14

**Trigger**: Pinned Vela insights were a flat two-item preview on the person page, with no way to find an older pin or group what they were about.

`[DECISION]` **Phase 0 against live `notes` (eigfvribtntbxyjutsma).** Pins are `notes` rows with `kind='vela_pin'`. Columns: `id`, `owner_id`, `about_person`, `pair_low`, `pair_high`, `body` (plaintext), `transit_snapshot`, `created_at`, `group_id`, `kind`, `payload`, `source_thread_id`, `withdrawn_at`, `withdrawn_reason`, `member_set_hash`, `tags`. No `theme` or `topic` column. `source_thread_id` is a conversation FK, not a topic. `tags` is the Record journal list (hard conversation, breakthrough, …), a different job. RLS is a single owner-only policy `"notes owner all"` `FOR ALL` `using (owner_id = (select auth.uid()))` `with check` the same. `relrowsecurity=true`, `relforcerowsecurity=false`. Production had 8 notes (3 note, 3 cohort_reading, 2 compare_reading) and **zero** `vela_pin` rows.

`[DECISION]` **Where pins render, and how many a heavy user could have.** The pin control stays on the Vela answer bubble (`＋ Pin to record` on `/app/vela`). The person page `#vela-on-them` module was the dedicated list, but `fetchVelaPins(..., 2)` only loaded the latest two. Pins also appear in the Record timeline as "Pinned from Vela". Mobile has no pin control. A heavy user who pins one insight per weekly conversation with a close person can accumulate ~50 pins on that person in a year; the two-item cap hid the rest. Search and grouping are pointless until that cap is raised. This branch loads up to 200, scoped to the person (and pairs containing them), and collapses the UI to the latest 5.

`[ADDED]` **Person-scoped search, curated theme, newest/oldest sort, and a latest-5 collapse** on the pinned-insight module. Search is plaintext FTS on `notes.body` (already indexed) plus client filter. Themes are a fixed list: how they're built, how you two work, this season, talking, tension, care, family, work. `suggestPinTheme` scores keyword hits against that list and returns null when nothing matches. It never invents an id. Pinning still writes `kind='vela_pin'` from the same bubble control; the insert now carries the suggested theme, and a picker lets the owner keep, change, or clear it.

`[ADDED]` **`notes.theme`** in `20260914220000_notes_vela_pin_theme.sql`, nullable, check-constrained to the curated list and `kind='vela_pin'`. No RLS change. Partial index `notes_vela_pin_theme_idx`. Applied to eigfvribtntbxyjutsma. A second-user JWT probe returned `notes_visible_to_B=0` and `themes_visible_to_B=0`. The check constraint rejected a theme on a non-pin and an invented theme id. Retest script: `docs/vela-pin-theme-rls-retest.sql`. Local `pnpm typecheck` and `pnpm test` are green (web 1077, astro 349, core 242, mobile 81, vela 28).
