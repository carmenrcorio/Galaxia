`[ADDED]` **`.github/workflows/nudge-delivery.yml`** — schedules `nudge-compute` and `nudge-send` (`needs: compute`), hourly (`13 * * * *`) plus `workflow_dispatch`. `nudge-send`'s own doc comment already required an hourly trigger (`isDueForNudgeSend` narrows each run to owners whose *local* clock just hit 9am — no single daily UTC cron can do that for every timezone). Running `nudge-compute` on the *same* hourly trigger (rather than once a day) is deliberate: a fixed-time daily compute run cannot precede every IANA offset's local-9am check (offsets span UTC-12..UTC+14, a wider spread than the 24-hour day a single run can front-run), and `nudge-compute`'s write is already idempotent (`onConflict: person_id,date, ignoreDuplicates: true`), so the extra hourly no-op passes are cheap and correctness-positive, not wasteful in a way that matters.

`[ADDED]` **`.github/workflows/trial-emails.yml`** — schedules `trial-emails` daily (`42 5 * * *`) plus `workflow_dispatch`. Same shape as `relational-transits.yml`: `curl --fail-with-body` (not plain `--fail` — the task's own quoted template used `--fail`, but that discards the response body on a non-2xx, which defeats the "diagnosable from the Actions log" requirement; matched the existing, already-reviewed `relational-transits.yml` convention instead), echoes HTTP status + JSON body, never the secret, fails the step on any non-2xx.
