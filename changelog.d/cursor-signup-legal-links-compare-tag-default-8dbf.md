## Signup ToS/Privacy link and Compare's neither-side-self tag default (branch `cursor/signup-legal-links-compare-tag-default-8dbf`) — 2026-08-19

**Trigger**: Pre-launch audit findings. (1) Signup created an account handling birth data, minors, and third-party data with no Terms of Service or Privacy Policy link anywhere on the page, only buried (and not even linked) in Settings. (2) Compare's relationship-type selector still defaulted to `friends` whenever neither Person A nor Person B was tagged `self`, even when one of them carried an unambiguous tag like `sibling` or `friend`.

`[ADDED]` **Passive ToS/Privacy line on `/signup`.** `apps/web/components/signup-form.tsx` now shows "By creating an account you agree to our Terms and Privacy Policy" beneath the Create account button, linking to the existing `/terms` and `/privacy` routes. No new legal copy was authored; the string is tagged FOUNDER-REVIEW.

`[CHANGED]` **`suggestCompareRelationType` in `@galaxia/astro` now also covers the neither-side-self case.** The existing self + other mapping is unchanged and still takes priority whenever exactly one side is tagged `self`. When neither side is `self`, a single tag is still never enough (a `people.relation` tag describes that person's relation to the USER, not to the other person in the pair) but an exact, symmetric, non-romantic match on both sides is now carried over: `sibling` + `sibling` to `siblings`, `friend` + `friend` to `friends`. `partner` + `partner` (and every other pairing) is deliberately excluded and still falls back to `friends`, so a romantic/Venus lens is never auto-selected from tags alone, even when both sides agree. `isMinorForSafety` (from `@galaxia/core`, never reimplemented) and the existing minor-clamp effect still run last, unchanged, on both web and mobile, and always win.

`[CHANGED]` **No drift between web and mobile.** Both `apps/web/app/app/compare/page.tsx` and `apps/mobile/app/(app)/compare.tsx` already delegated entirely to the shared `suggestCompareRelationType`/`defaultCompareRelationType` functions, so the neither-side-self fix applies identically to both surfaces with no page-level changes needed.
