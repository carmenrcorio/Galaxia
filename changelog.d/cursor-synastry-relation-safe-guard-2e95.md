## Synastry PASS 1 romance-coded copy fixed, structural guard added (branch `cursor/synastry-relation-safe-guard-2e95`) - 2026-09-10

**Trigger**: `SYNASTRY_PAIR` in `packages/astro/src/synastry-interpretations.ts` has no relation-type dimension in its lookup key — `interpretSynastryAspect(a, b, aspect)` renders the exact same string on a couple's Compare page and on a parent reading about their own child, unedited. An audit of every PASS 1 string (the 105 entries covering the 7 personal/social bodies, shipped before PASS 2's outer-planet pass and never founder-reviewed for this) found 15 strings across 6 pair-aspect keys, concentrated in `mars-venus`, that assumed a romantic reader: `chemistry`, `attraction`, `desire`, `passion`, `magnetic`, and one entry that told the reader to "want each other" and "rub each other." They had been live in production, rendering unreviewed on parent-child and ancestor comparisons, for the entire PASS-1-to-PASS-2 window.

`[FIXED]` **Rewrote all 15 violating PASS 1 strings in `synastry-interpretations.ts`.** Every rewrite preserves the real astrological dynamic (Mars-Venus IS a pull toward someone, an intensity about how the other moves) in language that also reads correctly for a parent-child, ancestor, sibling, friend, or coworker pairing. Two entries required a second pass after founder review: `mars-venus` conjunction long dropped an aspect-commentary aside ("This is the contact behind wanting to be near someone, full stop.") in favor of a sentence describing what the fusion of affection and wanting actually does; `mars-venus` square long's closing sentence ("Let it drive you toward each other, not into a fight") was rewritten because "drive you toward each other" only works as couple's advice — it now reads "Use it to close the distance between you, not to win the argument." Every rewritten aspect block is tagged `FOUNDER-REVIEW`. No string that already passed founder review (PASS 2's 120 outer-planet entries, or any PASS 1 string without a violation) was touched.

`[ADDED]` **Header comment above `SYNASTRY_PAIR`** explaining the constraint for the next author: `AspectKey` has no relation-type dimension, so a string written with a romantic reader in mind renders unedited on a parent-child or ancestor comparison. Points at the new test below.

`[ADDED]` **`packages/astro/src/__tests__/no-romantic-terms-in-synastry-copy.test.ts`.** Permanent gate, same pattern as `no-em-dash-in-compare-copy.test.ts`. Scans every `short`/`long` in `SYNASTRY_PAIR` for a fixed, audit-derived term list (`chemistry`, `desire`, `attraction`/`attract`, `magnetic`, `passion`, `want each other`, `rub each other`, plus `flirt`/`seduce` added pre-emptively since neither currently appears but both are the obvious next leak). Matching is case-insensitive and word-boundary-anchored (`attract` catches `attraction`/`attracts` but not an unrelated word); failure names the exact pair key, aspect, field, and matched term. Includes self-tests proving the regexes behave as specified.

`[CHANGED]` **`test/synastry-interpretations.test.ts`** updated one stale content assertion (`venus-mars square .long` no longer contains the old "You want each other" string) to match the PASS 1 rewrite; no test intent changed.
